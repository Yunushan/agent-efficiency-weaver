# Security policy

Do not commit secrets, API tokens, authentication files, private source code, real customer data, or infrastructure credentials. Review all generated MCP permissions and destinations before use. Configuration rendering does not install or launch MCP services and does not read ambient vendor settings.

Generated artifacts are staged files with a manifest of relative paths and hashes. `--force` is limited to owned artifacts whose current hash matches; manually edited files, unmanaged files, symbolic links, junctions and other reparse points, path traversal, and absolute paths are refused. Manifests must not contain secrets or absolute user paths. Hash matching is change detection, not a signature or audit record of tampering, and the writer does not claim cross-process race resistance or a bundle-wide atomic transaction.

Provider commands never accept API-key values as arguments and never read, expand, write, or log credentials. Provider setup never reads credential environment-variable values; generated setup text names variables only, such as `OPENROUTER_API_KEY`. OS detection may read platform indicators such as WSL and Termux markers, not provider credentials. Use only the vendor's documented environment-variable reference or settings interface. Storage guarantees are vendor-specific: Kilo and OpenCode may store credentials in local config or authentication files; no OS-keychain guarantee is implied. Do not guess a provider secrets configuration or stage credential files. Registry evidence sources must use credential-free HTTPS URLs; query URLs and token-bearing fragments are rejected before export.

Default generated MCP output is default-off, and the `enterprise-secure` profile generates zero MCP selections. Ambient and global vendor servers are not inspected, so generated profiles cannot disable them and do not imply control over a vendor's tools.

Avoid pointing write-enabled MCP tools at production Kubernetes, GitLab, cloud accounts, or databases. Use disposable fixtures, explicit approvals, and read-only access for infrastructure validation. Do not open remote listeners, expose ports, or weaken authentication to create mobile or remote handoffs. Report security issues privately to repository maintainers instead of publishing exploit details.
